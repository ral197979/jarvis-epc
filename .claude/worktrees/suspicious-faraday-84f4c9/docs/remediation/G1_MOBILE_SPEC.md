## Target end-state

Offline-capable field UX reaching parity with Procore on three flows: daily logs, punch lists, observations. Delivered via two vectors:

1. **PWA** — browser-installable, service-worker cached, IndexedDB offline queue. Ships first.
2. **Capacitor wrap** — iOS/Android binary built from the same web codebase, distributed via TestFlight + Play Internal Track.

Both share one codebase. Capacitor only adds platform shell + native plugin bindings.

## Architecture (PWA tier)

### Service worker strategy

| Asset class | Strategy | Cache name | Invalidation |
|---|---|---|---|
| App shell (HTML, JS, CSS) | Stale-while-revalidate | `shell-v{version}` | Version bump on release |
| API GET reads (`/api/v1/**`) | Network-first with 5s timeout fallback | `api-reads` | 1 hour TTL |
| Images (icons, logos) | Cache-first | `images-v1` | Manual bust |
| Document downloads | Cache-first, 100 MB cap | `documents` | LRU eviction |
| Writes (POST/PUT/PATCH/DELETE) | Network-only; queue to IndexedDB on failure | n/a | Replay on reconnect |

Proposed library: `vite-plugin-pwa` (v0.20+) with `workbox` runtime.

### IndexedDB offline queue schema

Database: `jarvis-offline-v1`

**Object store: `pending-mutations`**

| Field | Type | Notes |
|---|---|---|
| `id` | string (uuid) | Primary key |
| `tenantId` | string | For isolation |
| `userId` | string | For audit |
| `createdAt` | number (ms epoch) | For sort |
| `url` | string | API path |
| `method` | `'POST'` \| `'PUT'` \| `'PATCH'` \| `'DELETE'` | |
| `headers` | object | Incl. `Content-Type`, `X-Idempotency-Key` |
| `body` | string (JSON) | Serialized request body |
| `status` | `'queued'` \| `'inflight'` \| `'failed'` \| `'conflict'` | |
| `attempts` | number | Retry counter |
| `lastError` | string \| null | Most recent failure |

**Object store: `cached-reads`** — keyed by URL, TTL, value.

### Sync protocol

1. On reconnect, SW fires a `sync` event (Background Sync API where supported; interval polling fallback).
2. Main thread drains `pending-mutations` in FIFO order.
3. Each mutation gets a fresh `X-Idempotency-Key` header on first send; retained on retry so server can deduplicate.
4. 2xx → delete from store.
5. 4xx client error → mark `failed`; surface in UI conflict inbox.
6. 409 conflict → mark `conflict`; surface server version for user to merge.
7. 5xx / network → increment `attempts`; backoff (1s, 4s, 15s, 60s, 5m, 30m); cap at 6 attempts.

### Conflict-resolution policy

Per project memory rule — server-authoritative last-write-wins. When the backend detects a concurrent modification (optimistic locking on `updated_at`), it returns 409 + the authoritative row. The client:

- Writes an entry to `audit_log` via the existing pattern.
- Surfaces a non-blocking toast ("Your offline edit to RFI-42 was superseded by PM's edit at 14:32 — review").
- Stores both versions for owner review.

**Principle:** never silently drop user work. Every conflict creates an auditable trail.

## Architecture (Capacitor tier)

### Project layout

```
/mobile                          (new directory at repo root)
├── capacitor.config.ts
├── ios/                          (generated by `npx cap add ios`)
├── android/                      (generated by `npx cap add android`)
├── resources/
│   ├── icon.png                  (1024×1024 source)
│   └── splash.png                (2732×2732 source)
└── scripts/
    └── build-and-sync.sh         (runs `npm run build` then `npx cap sync`)
```

### Native plugins required

| Plugin | Purpose | Package |
|---|---|---|
| Camera | Daily log + punch-list photos | `@capacitor/camera` |
| Filesystem | Local-side document cache | `@capacitor/filesystem` |
| Geolocation | Observation geo-tagging | `@capacitor/geolocation` |
| Push Notifications | Critical-alert delivery | `@capacitor/push-notifications` + FCM |
| Network | Offline-state detection | `@capacitor/network` |
| App | Deep-link handling | `@capacitor/app` |
| Haptics | Form confirmation feedback | `@capacitor/haptics` |

### Native capabilities declaration

**iOS** (`Info.plist` additions):

- `NSCameraUsageDescription` — "Used to attach photos to daily logs and punch list items."
- `NSLocationWhenInUseUsageDescription` — "Used to geo-tag field observations."
- `NSPhotoLibraryAddUsageDescription` — "Used to save captured photos to the device."

**Android** (`AndroidManifest.xml`):

- `android.permission.CAMERA`
- `android.permission.ACCESS_FINE_LOCATION` + `ACCESS_COARSE_LOCATION`
- `android.permission.POST_NOTIFICATIONS` (API 33+)
- `android.permission.INTERNET` (implicit)

### Push notification provisioning

- iOS: APNs key (`.p8`), stored in CI secret `APNS_AUTH_KEY`; team ID + key ID in env.
- Android: FCM project; `google-services.json` under `mobile/android/app/`; CI secret `FCM_SERVER_KEY`.
- Backend: new endpoint `POST /api/v1/notifications/push-token` to register device tokens keyed by user + tenant.

## Risks

| Risk | Severity | Mitigation |
|---|---|---|
| Offline conflict storms in pilot use | Medium | Last-write-wins + audit log on every conflict; owner-review queue |
| iOS review rejection | Medium | Privacy manifest complete before submission; internal-first TestFlight cohort |
| Capacitor plugin version drift | Low | Lock major versions; CI job runs `npx cap doctor` |
| Service worker cache poisoning | Low | Versioned cache names; cache busted on each release; SW cleanup on activate |
